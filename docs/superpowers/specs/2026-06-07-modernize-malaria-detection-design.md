# Modernize Malaria Detection Project — Design

## Goal
Rebuild the existing `Malaria_detection` GitHub repo (currently a single 2020-era
FastAI Jupyter notebook + README + screenshot) into a clean, modern,
LinkedIn-presentable ML portfolio project, then push it to replace the old
content at the same repo URL (`github.com/mauryasameer/Malaria_detection`).

## Approach
- Migrate from FastAI to plain PyTorch + torchvision (more widely recognized
  stack in ML-eng hiring contexts).
- Retrain from scratch on the public NIH Malaria Cell Images dataset
  (parasitized vs. uninfected cell images, ~27k images, 2 classes).
- Training happens on Colab/Kaggle GPU (no local GPU here); resulting weights +
  metrics get committed back to the repo.
- Ship a live Gradio demo deployed on Hugging Face Spaces (user already has an
  HF account: `mauryasameer`).
- Add a custom AI-generated hero banner image to make the README pop.

## Data flow / pipeline
1. NIH Malaria Cell Images dataset (public, 2 classes: parasitized / uninfected)
   is loaded and split (train/val) via `dataset.py` with torchvision transforms.
2. `train.py` fine-tunes a pretrained ResNet-18/50 on the dataset, saves the
   best checkpoint plus a metrics JSON (accuracy, precision, recall, confusion
   matrix).
3. `train_colab.ipynb` mirrors `train.py` for a one-click GPU run on Colab —
   produces the weights file + metrics, which get committed to the repo (or
   pushed to an HF model repo if size warrants it).
4. `infer.py` and `app.py` load the checkpoint for prediction.
5. `app.py` (Gradio) lets a user upload a cell image and returns class +
   confidence; deployed on HF Spaces under the user's account for a live demo
   link referenced from the README.

## Testing / error handling
Lightweight, scaled to a portfolio project:
- Smoke tests for model forward pass (shape checks) and dataset loader
- `train.py` / `infer.py` validate file/checkpoint paths exist with clear error
  messages — no handling for impossible/exotic edge cases

## Out of scope
- No backend service / API beyond the Gradio app
- No CI pipeline (optional future addition, not required for this pass)
- No retraining automation beyond the Colab notebook
